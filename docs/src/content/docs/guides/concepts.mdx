There are a few key concepts that are important to understand when working with Liquid Auth:
- **Linking**
- **Passkeys**
- **Peer-to-Peer**


## 🔗 Linking

A link authorizes a remote client to access the service by generating a `RequestId` and awaiting device attestation of a Passkey.

## 🔒 Passkeys

Passkeys, also referred to as FIDO2/WebAuthn [PublicKeyCredential](https://developer.mozilla.org/en-US/docs/Web/API/PublicKeyCredential), are crucial for user registration and authentication. They are generated by an authenticator device and consist of a KeyPair.

### FIDO2 Extension

Authenticators must support the `Liquid Extension` to attest a `KeyPair` not controlled by them. This extension adds an additional signature to associate the `KeyPair` with the `Passkey` and includes an optional `requestId` to link the `KeyPair` to a specific session. When two clients are linked, they can establish a peer-to-peer connection.

## 🔄 Peer-to-Peer

[WebRTC](https://developer.mozilla.org/en-US/docs/Web/API/WebRTC_API) is used for establishing a peer-to-peer connection between two clients.

#### Offer

The client sends a Session Description Protocol (SDP) message to the server, which includes details about the client's media capabilities and and information about the data channel.

<LinkCard
  title="Offer Guide"
  description="Guide on Offer descriptions."
  href="/guides/peer-to-peer/offer"
/>

#### Answer

"A Session Description Protocol (SDP) message is sent back to the client that created the offer. The answer client uses this information to generate an SDP answer, which is then sent to the offer client."

<LinkCard
  title="Answer Guide"
  description="Guide on Answer descriptions."
  href="/guides/peer-to-peer/offer"
/>

#### Candidate

An ICE Candidate represents a network address that can be used to establish a connection with a peer.
