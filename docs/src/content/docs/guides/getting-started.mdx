## Introduction

In this guide, we will explore Liquid Auth through a practical example use case. This will provide you with a brief and quick understanding of how Liquid Auth can be applied in real-world decentralized applications (dApps).

Liquid Auth consists of two main components: the **Liquid Auth Server** and the **Liquid Auth Clients**. Together, they provide authentication and signaling services for decentralized applications (dApps).


## 🚀 Example Use Case

The **dApp** provides the service, while the **Wallets** act as clients. The **Wallet** receives the `Origin` and `RequestId` from the **dApp** to authenticate with the service using the provided `Origin`.

#### 📝 Requirements

- **Wallets** must implement the **Offer** `SignalClient` and the **WebAuthn Extension** to establish a secure peer-to-peer connection with the **dApp**.
- **dApps** must implement the **Answer** `SignalClient` and host the authentication service.
